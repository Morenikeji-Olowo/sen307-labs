# Lab 4 Notes: Referential Integrity

In Part 4, trying to delete the "Library and Information Science" department gave **Error 1451: Cannot delete or update a parent row: a foreign key constraint fails**. MySQL refused because the Student table has a foreign key (`dept_id`) pointing to Department, and one student ("Transfer Student", 20239999) still belonged to that department. Deleting the department would have left that student pointing to a department that no longer exists, an orphan row, which breaks referential integrity. I fixed it by first updating the student's `dept_id` to Software Engineering, so no rows depended on the department anymore, and then the delete succeeded. Other fixes I could have used: deleting the dependent student before the department (but that loses the student's record), or defining the foreign key with `ON DELETE SET NULL` (the student's `dept_id` becomes NULL automatically, if the column allows NULL) or `ON DELETE CASCADE` (the student is deleted automatically along with the department, which is risky because data is lost silently).
